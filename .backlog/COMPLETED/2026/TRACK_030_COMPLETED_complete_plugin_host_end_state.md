Problems (PORE)
- P1: As a maintainer completing the MyMCP roadmap, I can finish every current phase while the endpoint, application title, official client connection, and permission prefixes still identify the host as Mnemosyne, because the approved target preserves current compatibility but never requires the final MyMCP public-host identity cutover.
- P2: As an external plugin author unknown to the project, I cannot build a safely installable native MyMCP plugin, because the target fully describes source-controlled bundled packages but does not define external distribution, side-effect-free metadata discovery, activation context, configuration, dependency, trust, naming, or data-ownership contracts.
- P3: As a user installing third-party code, I cannot know what protection MyMCP provides, because the target applies the same in-process author-contract language to bundled and future external plugins while deferring the threat model and isolation boundary.
- P4: As a plugin author or host maintainer, I cannot evolve beyond Tools or across releases safely, because capability-kind identity, protocol scope, lifecycle states, runtime publication, version evolution, update/rollback, removal/purge, and compatibility rules are incomplete.
- P5: As a user expecting a client-neutral governance gateway, I cannot rely on server-enforced per-client policy or exact mutation approval, because the target does not yet define authenticated local client principals, host-verifiable approval evidence, policy-filtered discovery, or bounded security audit.

Objective
- Complete and reconcile the architectural end state so the roadmap necessarily delivers MyMCP as the public host, Mnemosyne as a coherent built-in plugin, and a safe explicitly scoped path for native non-MCPB external plugins before Phase 1 implementation begins.

Non-negotiables
- This Track corrects durable architecture and roadmap material only; it does not implement plugin APIs, manifests, packaging, identity migration, lifecycle, isolation, gateway policy, or runtime behavior.
- Any later behavior implementation follows TDD: a focused failing test, the smallest passing implementation, then refactoring and validation.
- The final host-controlled product, endpoint, application, repository, and official client identity is MyMCP; Mnemosyne remains the built-in plugin, memory Tool, configuration, storage, and record identity.
- MyMCP plugins are not MCPB bundles. MCPB may package MyMCP as one complete server later, but it is not the native plugin format or internal author boundary for this roadmap.
- Preserve local-first operation, single-user assumptions until explicitly revised, filesystem truth, least privilege, explicit Tools, deterministic failure, operator control, and visible exact mutation approval.
- Unknown-author external code must not be treated as equivalent to source-controlled trusted built-ins or run in the host process merely because it has a valid manifest.
- A manifest declaration is metadata, not executable discovery, artifact trust, consent proof, filesystem/network authority, or process isolation.
- Never store plaintext plugin secrets in manifests, host configuration, installation records, lifecycle state, status output, or logs.
- Plugin removal preserves configuration and user data by default; irreversible purge is a separate narrowly scoped operation requiring explicit approval.
- Do not add shell execution, arbitrary source-directory or configured-module scanning, unrestricted filesystem/network access, hidden enablement, or marketplace/network installation in the initial native-plugin contract.
- Every resulting implementation Track must establish a stable part of the corrected target rather than freeze a bundled-only contract that external plugins later require breaking.

Risks / decisions
- Risk: Correcting every omitted lifecycle/security detail can over-specify implementation prematurely.
- Mitigation: Fix end-state invariants, trust boundaries, state transitions, and phase gates now; leave replaceable algorithms, concrete libraries, UI, and wire encoding to later Tracks.
- Risk: Calling external native plugins “the same contract” as bundled plugins can imply unsafe in-process ABI parity.
- Mitigation: Separate shared manifest/logical capability semantics from acquisition and execution adapters; unknown external code requires a versioned isolated boundary before activation.
- Risk: Python wheel installation in one shared environment can create dependency conflicts or mutate the running host.
- Mitigation: Decide the managed-environment and atomic staging model before lifecycle implementation; never install into the arbitrary host interpreter or `mymcp/plugins/` source package.
- Risk: Public endpoint identity migration can break configured clients or silently weaken mutation approval rules.
- Mitigation: Make it a dedicated compatibility Track with atomic client key/permission migration, version marker, restart/reconnect instructions, and direct consent checks.
- Risk: Host-verifiable approval and client identity can expand the currently small HTTP surface or create secret-management obligations.
- Mitigation: Define the required security semantics first, retain machine-local single-user scope, and design the narrowest explicit control boundary in its own later Track.
- Decision: The finished host-controlled identity is MyMCP. Current Mnemosyne server identity is a phase-bounded compatibility state, not the architectural end state.

Decision log
- Decision: TRACK_029 remains the historical record of the first approved concrete plugin target; TRACK_030 corrects its incomplete end-state assumptions rather than rewriting its completion evidence.
- Decision: This Track is documentation and roadmap architecture work. Runtime implementation remains prohibited while DRAFT and remains out of scope after activation.
- Decision (Q1): The final host-controlled identity is MyMCP: MCP server machine name `mymcp`, FastAPI title `MyMCP`, official client/agent key and generated permission prefix `mymcp`, Python distribution/package/commands `mymcp`, and canonical repository `flyset/MyMCP`. `/mcp`, `/health`, `/version`, the MCP protocol version, `list_tools`, and every Mnemosyne `memory_*` name remain otherwise unchanged. A dedicated compatibility Track after Mnemosyne extraction atomically changes endpoint, application, repository metadata, and official client policy in the first `0.2.0` build; `0.1.x` remains the Mnemosyne-public-host era. Extraction cannot complete the roadmap, unknown external plugins cannot activate, and gateway operation cannot begin before this cutover. Mnemosyne keeps plugin ID `mnemosyne`, its independent plugin version, all `memory_*`, `MNEMOSYNE_*`, `~/.mnemosyne`, and record identities.
- Decision (Q2): Bundled and external plugins share immutable logical manifest, definition, capability, effect/consent, binding, activation-result, and lifecycle semantics. Trusted source-controlled bundled plugins use an explicit reviewed in-process adapter. Unknown external plugins never use that Python callable as their security boundary and instead execute through a separately versioned isolated worker adapter. Generic composition consumes validated activated capabilities and is independent of the adapter.
- Decision (Q3): Native external distribution is one prebuilt plugin wheel plus a complete prebuilt hash-locked dependency-wheel closure. MyMCP accepts no source distribution, editable/VCS install, source build, setup hook, or network resolution. One inert manifest lives at `<distribution>.dist-info/mymcp-plugin.json`; standard entry-point metadata may identify the worker adapter but is never imported during discovery or by the host process. The host inspects archives before execution, binds approval and receipt to every artifact digest, installs offline into one immutable environment per `(plugin_id, plugin_version, artifact_digest)`, and never installs into the host interpreter, repository package, bundled-plugin tree, or another plugin environment.
- Decision (Q4): `PluginDefinition` is immutable data containing identity, compatibility, complete kind-qualified capability declarations, effect/consent, bounded ordinary-configuration schema, declared secret-reference slots, data-schema version, and requested authority; it contains no handler, command, import, secret, open resource, or host object. The host supplies an immutable `PluginContext` containing exact identity/generation, validated ordinary configuration, opaque declared secret handles, issued data/state/cache capabilities, deadline/cancellation, and a bounded event sink—never a service locator, shell, ambient environment, unrestricted path, principal credential, policy database, or registry mutation access. Activation returns selected complete Tool definitions and adapter-owned invokers plus bounded health/shutdown operations. The logical API is asynchronous, deadline- and cancellation-aware; current synchronous Mnemosyne handlers are wrapped without changing behavior. External shutdown is cooperative then forcibly killable; bundled shutdown remains trusted and cooperative.
- Decision (Q5): MyMCP host state is rooted under `~/.mymcp/` and separates host desired state/bindings, schema-validated ordinary per-plugin configuration, immutable installation receipts/environments, and host-issued private `data/`, `state/`, and disposable `cache/` ownership. Configuration and receipts contain typed secret references only, never plaintext secret values. A plugin cannot nominate arbitrary host paths or see another plugin's directories. Secret provider/acquisition is separate and deferred; plugins requiring unavailable secrets cannot activate. Mnemosyne's compatibility adapter preserves `MNEMOSYNE_*`, `~/.mnemosyne/config.toml`, and `~/.mnemosyne/memory` without relocation or duplicate MyMCP configuration.
- Decision (Q6): Qualified capability identity is `(plugin_id, capability_kind, capability_local_id)`. Host API v1 supports exactly capability kind `tool`; Resources or Prompts require later API evolution. Plugin IDs use lowercase kebab identity, Tool-local IDs use lowercase underscore identity, and neither grammar admits the separator `__`. The deterministic external default public Tool name is `<plugin-id>__<tool-local-id>`. Binding precedence is host-reserved names/prefixes, host-pinned compatibility bindings including Mnemosyne `memory_*`, persisted operator bindings, then deterministic external default. Manifests never claim public names; collisions reject the candidate generation without overwrite, suffix fallback, shadowing, or aliases. Existing persisted bindings remain stable if a future default algorithm changes; `list_tools` and `mymcp_*` remain host-reserved.
- Decision (Q7): Installation (`absent`, `staged`, `installed`), desired enablement (`disabled`, `enabled`), observed process state, immutable runtime-generation state, and plugin-data state are separate dimensions. Initial lifecycle may remain restart-published, but every publication constructs and validates a complete candidate generation, atomically exposes it, pins in-flight calls to their original generation, then drains the prior generation. Required-plugin failure aborts publication and leaves the active generation intact; optional failure is visible and audited, never silently omitted. Disable stops new calls before drain/shutdown; quarantine overrides desired enablement. Update stages beside the active artifact and cannot migrate data implicitly. Rollback requires code/data compatibility or a reversible migration. Removal requires inactivity and preserves configuration, secret references, data, state, and cache; purge is a distinct destructive exact-target operation after drain/termination and requires explicit approval without claiming secure erasure.
- Decision (Q8): Installation may precede isolation, but unknown external code cannot activate without exact artifact/dependency digests and provenance, immutable operator approval receipt, definition/manifest parity, one supervised process group, private bounded authenticated IPC, deadlines/cancellation/concurrency/message limits, minimal environment, read-only code, only approved issued directories, default-denied network, bounded CPU/memory/process/file/output/time resources, and reliable descendant killability. Unsupported mandatory controls fail activation rather than falling back to unrestricted or in-process execution. Signing may add provenance later but never replaces digest approval, compatibility, authorization, or isolation. Trusted bundled plugins explicitly retain host-process authority.
- Decision (Q9): The one human user remains the sole user; a client principal identifies an enrolled local client application, not a tenant. Loopback reachability, MCP `clientInfo`, connection key, process ID, user agent, and request ID are not authentication. Host-created authenticated sessions carry principal, policy revision, runtime generation, and negotiated protocol context. `tools/list`, `list_tools`, and dispatch use the same policy-filtered kind-qualified view, while dispatch independently reauthorizes every call. Operator enablement, policy allowance, and exact-call approval are independent. Approval evidence is trusted-local, single-use, short-lived, and binds the authenticated principal/session, qualified capability, public binding, runtime/policy/schema generation, trusted effect, and complete arguments after host compatibility normalization; replay or any mismatch fails before plugin invocation. A host-owned bounded content-free audit records authentication, policy, approval, dispatch, generation, process, lifecycle, and purge outcomes without arguments, results, memory text, headers, paths, environment values, credentials, raw request IDs, plugin output, exception details, or tracebacks.
- Decision (Q10): Versions remain independently owned: MyMCP release owns distribution version; the endpoint owns its public server marker; MCP negotiation owns protocol version; MyMCP owns integer host-plugin API, strict manifest schema, and external worker protocol versions; plugin authors own semantic plugin, capability-contract, ordinary-configuration-schema, and plugin-data-schema versions; the installer owns exact artifact/dependency digests; policy owns immutable policy revision; and host runtime owns an opaque unique generation ID. Identity never includes a version. Compatibility is validated explicitly and never inferred because values currently coincide. Mnemosyne record schema versions remain plugin-owned.
- Decision (Q11): Permanent boundaries are: MCPB is not the native plugin format; unknown external code is never imported into the host process; manifests grant no authority; plugins receive no shell, arbitrary import, unrestricted filesystem/network, ambient secrets, public-binding ownership, or shared dependency environment. Deferred replaceable choices include installer/lock implementation, worker framing/IPC, sandbox backend and quota values, signature PKI, secret provider, live-reload control surface, migration snapshot format, Resources/Prompts, marketplace/downloads/source builds, cross-plugin dependencies, remote/multi-user operation, and reusable host services before a second real plugin proves them generic.
- Decision (Q12): The first corrected runtime Track is `Kind-qualified HostRuntime and trusted bundled activation adapter`. It introduces frozen logical identity/capability/effect/consent/binding/generation values, an immutable `HostRuntime` retaining the current registry plus ordered plugin origins and metadata, an explicit trusted adapter around the current Mnemosyne integration, runtime injection into MCP handling, and explicit application/bootstrap assembly without ordinary-package import composition. It preserves exact public behavior and defers manifests, package moves, external wheels/workers, lifecycle mutation, endpoint identity cutover, gateway policy, and public metadata.
- Decision: Corrected phase gates are: architecture/roadmap approval; kind-qualified runtime foundation; strict bundled definition/manifest parity and complete Mnemosyne extraction; mandatory MyMCP public-host cutover; inert external distribution/install; enforceable isolated activation; generation-based lifecycle; authenticated gateway governance; and only then proven reusable host services. External artifacts may be installed before isolation exists but cannot become active.
