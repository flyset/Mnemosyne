# MyMCP 0.7.0 delivered build notes: OAuth resource-server integration

> This documents the delivered `0.7.0` build change. It does not assert that a
> Git tag, package publication, or hosted release has been created.

## Delivered

MyMCP/`mymcp` `0.7.0` adds host configuration schema 5 and the
`oauth-jwt-jwks-v1` OAuth resource-server Authentication method. OAuth is
startup-fixed: an enabled declaration selects one canonical HTTPS issuer and
loads metadata plus same-origin JWKS into one immutable validation snapshot before
the plugin runtime is published. The method returns only a bounded adapter-local
subject through unchanged Authentication contract v1; it establishes identity,
not Tool authority.

The concrete validator uses the narrowly isolated
`PyJWT[crypto]>=2.13.0,<3.0` runtime dependency. Accepted access tokens have a
maximum five-minute lifetime. MyMCP performs no runtime key refresh or immediate
revocation check, so key removal is observed only after restart and an otherwise
valid token may remain accepted until its bounded expiry.

Schema 5 requires exact `[authentication.oauth_jwt]` containing only non-secret
`issuer` whenever an OAuth declaration exists, including a disabled declaration,
and prohibits the table otherwise. Enabled OAuth requires
`anonymous_enabled = false` and claims exactly the Authorization/Bearer evidence
route. OAuth and `operator-bearer-v1` are mutually exclusive in a schema-5
document, including disabled declarations: HTTP never chooses an adapter from
token shape. Changing configuration or validation keys requires a restart; there
is no refresh, introspection, fallback, hot configuration, or provider management.

When and only when OAuth is enabled, MyMCP serves RFC 9728 protected-resource
metadata at exactly `/.well-known/oauth-protected-resource/mcp`. The response has
`Cache-Control: no-store` and exactly `resource`, one
`authorization_servers` value, and `bearer_methods_supported: ["header"]`; it
has no scopes or additional fields. The resource and metadata URL derive only
from validated loopback address and port, never request `Host` or forwarded
headers.

OAuth authentication failures on `/mcp` occur before streaming, body parsing, MCP
logging, or dispatch. They remain body-free HTTP `401` and carry exactly
`WWW-Authenticate: Bearer resource_metadata="<derived metadata URL>"`, without
token-derived error detail. Operator-bearer and anonymous-only configurations
retain challenge-free behavior.

## Compatibility and exclusions

- Schemas 1–4 and absent-file behavior remain unchanged; schema 5 is additive.
- The literal loopback HTTP resource is a deliberate local interoperability
  exception, not HTTPS, remote deployment, TLS termination, or multi-user support.
- MyMCP is not an authorization server and does not serve authorization-server or
  OpenID Provider metadata, dynamic client registration, or `/register`.
- MCP protocol negotiation and MCP methods/messages/Tools/results/errors remain
  unchanged. The host remains MyMCP while its package/server and `/version`
  marker advance to `0.7.0`; one conditional protected-resource metadata route
  is added. Host plugin API 1, manifest schema 1, external plugin-author contract,
  plugin/capability/data/runtime identities, Mnemosyne configuration/storage/record
  schemas, and plugin composition remain unchanged.
- Authentication contract v1 and `operator-bearer-v1` verifier-source format 1
  remain unchanged. Sessions, Governance, Tool authorization, scopes-to-policy
  mapping, exact-call approval, security audit, plugin trust, and user consent
  remain outside this build.
