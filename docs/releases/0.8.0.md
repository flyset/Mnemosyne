# MyMCP 0.8.0 delivered build notes: MCP principal/session integration

MyMCP/`mymcp` `0.8.0` advances the advertised MCP revision to `2025-11-25` and
adds a host-owned, process-local session boundary for registered principals.

## Delivered behavior

- Every `/mcp` request authenticates before session lookup.
- A successful response-bearing registered `initialize` offering `2025-11-25`
  returns exactly one opaque `MCP-Session-Id` header.
- Later registered POST and GET traffic requires singleton `MCP-Session-Id` and
  `MCP-Protocol-Version: 2025-11-25` headers; authenticated `DELETE /mcp`
  terminates the exact valid session with `204`.
- Sessions bind the complete normalized principal, runtime generation, and
  negotiated protocol version; they are bounded to 128 active entries, expire
  after 30 minutes of inactivity or eight hours absolute lifetime, and disappear
  at process restart.
- Missing, malformed, prohibited, or unsupported session transport is body-free
  `400`; unknown, expired, terminated, stale, or principal-mismatched sessions
  are body-free `404`; capacity exhaustion is body-free `503`.
- Explicit anonymous access remains stateless and receives no session identifier.

## Unchanged boundaries

Authentication contract v1, adapters, configuration schemas 1–5, OAuth metadata
and challenge behavior, host plugin API 1, manifest schema 1, external plugin
contract, plugin/capability/data versions, runtime-generation semantics, bindings,
Mnemosyne configuration/storage/record schemas, and all `memory_*` Tool contracts
remain unchanged. Sessions do not authorize Tools, replace client mutation consent,
grant approval, retain credentials, or become visible to generic MCP, plugins, or
Mnemosyne. Governance, Tool authorization, approval, and audit remain deferred.
