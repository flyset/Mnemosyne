# MyMCP 0.6.0 delivered build notes: operator-provisioned bearer authentication

> This documents the delivered `0.6.0` build change. It does not assert that a
> Git tag, package publication, or hosted release has been created.

## Delivered

MyMCP/`mymcp` `0.6.0` adds the host-owned `operator-bearer-v1` Authentication
adapter and host configuration schema 4. The adapter validates exactly routed
operator-provisioned bearer credentials and returns a registered principal through
the existing Authentication-v1 principal contract.

An enabled adapter claims only `(authorization, bearer, null)`. The accepted
credential is sent in exactly one header:

```text
Authorization: Bearer mymcp1.<32-lowercase-hex-id>.<43-character-unpadded-base64url-secret>
```

`Bearer` is ASCII case-insensitive and followed by one ASCII space. The secret
encodes 32 independently generated random bytes. Duplicate headers, whitespace
variants, Unicode, wrong schemes, malformed/unknown/revoked credentials, and all
other unsupported or rejected submitted evidence return the existing empty HTTP
`401` before MCP body parsing, streaming, logging, or dispatch; failed evidence
never falls back to anonymous.

Schema 4 retains schema-3 server, plugin, anonymous, and adapter syntax and adds
the exact non-secret `[authentication.operator_bearer]` table with only absolute,
unexpanded `verifier_path`. It is required whenever an `operator-bearer-v1`
declaration exists, including disabled declarations, and prohibited otherwise.
The file is accessed only for an enabled adapter.

The selected verifier is a separately managed strict UTF-8 JSON format-1 complete
snapshot, limited to 16 KiB and 32 exact `{id, subject, digest}` records. Each
digest is the unpadded base64url SHA-256 digest of a credential secret. Duplicate
IDs and JSON keys fail closed; duplicate subjects intentionally support rotation.
The protected source is startup-fixed and checked for safe type, links,
permissions, replacement, and mutation. Plaintext credentials are not stored by
MyMCP.

Operators provision offline: stop MyMCP, independently generate the credential,
deliver it once by a chosen secure channel, atomically replace the complete
protected verifier snapshot, then restart. Rotation adds a new ID for the same
subject before an old ID is removed in a later replacement and restart. Revocation
removes the ID and restarts. No MyMCP credential issue or management API, runtime
reread, file watch, merge, revoked marker, hot rotation, or hot revocation exists.

## Compatibility and exclusions

- Authentication contract remains v1: principal, evidence, request context,
  adapter result, exact routing, anonymous admission, and host canonical identity
  construction are unchanged.
- Schemas 1–3 and absent-file anonymous defaults remain unchanged; schema 4 is a
  new strict host-configuration document shape.
- MCP protocol negotiation, routes, endpoint identity, and empty-401 failure
  shape remain unchanged.
- Host plugin API 1, manifest schema 1, external plugin-author contract 1,
  plugin/capability identities and versions, bindings, plugin data/configuration,
  runtime-generation semantics, Mnemosyne configuration/data/record schemas,
  Tool discovery/dispatch, and all Mnemosyne behavior remain unchanged.
- OAuth/OIDC, sessions, Governance/ACL policy, filtered discovery or dispatch,
  Tool authorization, exact-call approval, security audit, credential-management
  endpoints, secret-management infrastructure, remote trust, and multi-user
  operation remain outside this build.
