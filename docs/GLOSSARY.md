# Glossary

- **Cold memory** — conventional shorthand for durable records retrieved only when relevant; they remain user-governed and easy to delete.
- **Consent** — explicit user authorization for a durable record or state-changing action; current Mnemosyne mutation Tools rely on per-call MCP-client approval, while the target gateway additionally requires host-verifiable single-use exact-call evidence. A model-provided field is never consent.
- **Guided** — the direction of authority in which the user guides Mnemosyne's organization; an agent may retrieve context and propose bounded placement or lifecycle changes, but the user remains the authority over meaning and approves each mutation.
- **Hot memory** — conventional shorthand for a small, bounded working set loaded into temporary model context at session start from durable records.
- **MCP tool** — a narrowly scoped capability exposed through the Model Context Protocol.
- **Architectural minimalism** — the MyMCP rule that each smallest implementation step must establish part of the declared target architecture rather than create an intentionally temporary boundary for unspecified later refactoring.
- **Host plugin API** — the versioned, host-owned Tools-only logical contract under `mymcp/plugin/` for plugin identity, inert manifests and definitions, kind-qualified capabilities, effect/consent, configuration/data declarations, activation, public bindings, compatibility, validation, and composition. Phase 1 implements the kind-qualified contribution/runtime seam; the first Phase 2 unit implements immutable definition contracts, manifest-v1 parsing, and static parity validation. Activation and the remaining target boundaries are deferred.
- **Plugin manifest** — strict inert plugin metadata. Schema version 1 declares plugin identity/version, host-API interval, complete kind-qualified capability inventory and contract versions, effect/consent, bounded ordinary-configuration shape, secret-reference slots, plugin-data version, and requested authority. The implemented byte parser accepts at most 64 KiB of strict UTF-8 JSON and rejects duplicate keys. Bundled declarations package `manifest.json`; external wheels will package the same logical manifest at `<distribution>.dist-info/mymcp-plugin.json`. A manifest contains no executable command, full Tool schema, configuration/secret value, public Tool name, lifecycle instruction, granted authority, consent proof, or isolation claim.
- **Plugin definition** — immutable data agreeing exactly with the manifest's identity, compatibility, capabilities, configuration shape, secret slots, data version, and requested authority. Current static bootstrap validates it against the packaged manifest and selected contribution before generation construction. It contains no handler, command, import, secret, running task, open resource, ambient host object, or publication capability.
- **Plugin context** — the bounded immutable activation context issued by the host: exact plugin/generation identity, validated ordinary configuration, opaque declared secret handles, issued data/state/cache capabilities, deadline/cancellation, and a bounded event sink. It is not a host service locator, shell, ambient environment, unrestricted path, client principal, policy database, or audit store.
- **Plugin activation** — the asynchronous logical operation that returns the selected declared capabilities, complete authoritative Tool definitions, adapter-owned invokers, bounded health, and idempotent shutdown. Trusted bundled adapters may wrap in-process handlers; external adapters proxy to supervised isolated workers.
- **Bundled plugin** — a concrete source-controlled implementation under `mymcp/plugins/` using the shared logical plugin contract through a reviewed in-process adapter. Bundled status grants trusted host-process execution and therefore is not an isolation claim. `mymcp/plugins/mnemosyne/` is the extracted Mnemosyne bundled implementation; external installation and isolation remain deferred.
- **Native external plugin** — an initial MyMCP plugin distributed as one prebuilt Python wheel plus a prebuilt hash-locked dependency-wheel closure, validated through inert metadata, installed offline into its own immutable managed environment, and activated only through a supervised isolated worker. It is not MCPB and is never imported into the host process.
- **Plugin trust class** — the explicit distinction between reviewed source-controlled bundled code with host-process authority and unknown external code requiring digest approval, supervision, enforceable default-deny authority, resource bounds, and killability. Shared logical contracts do not erase this execution boundary.
- **Qualified capability identity** — the target stable internal triple `(plugin_id, capability_kind, capability_local_id)` retained independently of version and the flat endpoint-visible name. Host API v1 admits only capability kind `tool`; adding Resources or Prompts requires API evolution.
- **Public Tool binding** — a host-owned target mapping from one qualified capability identity to one endpoint-visible MCP Tool name. Host-reserved and pinned compatibility bindings precede persisted operator bindings and deterministic external defaults. Mnemosyne's existing `memory_*` names remain canonical; manifests do not claim endpoint names and `list_tools` remains host-reserved.
- **Plugin artifact identity** — the installer-owned exact digest identity of one plugin wheel and its complete dependency closure. It is bound to approval and installation receipts and is not replaced by plugin version or signature.
- **Runtime generation** — one host-issued opaque unique identity for a complete immutable published runtime surface. It is not a package, protocol, plugin, policy, process, or memory-list-cursor version; candidate failure cannot partially alter the active generation.
- **Host runtime** — the immutable `HostRuntime` process value containing the final Tool registry, ordered plugin inventory, kind-qualified origins, trusted effect/consent metadata, public bindings, and opaque runtime-generation identity. It owns no Mnemosyne policy and is assembled through explicit `build_production_runtime` only after fixed manifest/definition/contribution parity; artifact identities and external activation remain deferred.
- **Local client principal** — one operator-enrolled and authenticated machine-local client application or installation in the target gateway, not another human, tenant, or Mnemosyne data partition. Loopback reachability, MCP `clientInfo`, connection key, process ID, user agent, and request ID do not establish it.
- **Exact-call approval evidence** — target host-verifiable, single-use, short-lived authorization bound after host argument normalization to the principal, session, qualified capability, public binding, runtime generation, policy revision, Tool schema, trusted effect, and complete invocation. Replay, mismatch, denial, expiry, auto-approval, wildcard approval, or a model-provided field fails before plugin invocation.
- **Security audit** — target host-owned bounded content-free records for authentication, policy, approval, dispatch, runtime generation, worker, lifecycle, and purge outcomes. Plugins cannot write or suppress it; it excludes request/result content, memory text, headers, paths, environment values, credentials, raw request IDs, plugin output, exception details, and tracebacks.
- **MyMCP public-host cutover** — the mandatory dedicated post-Mnemosyne-extraction `0.2.0` migration. Released MyMCP/`mymcp` `0.2.0` changes endpoint/server name to `mymcp`, FastAPI title to `MyMCP`, package metadata and canonical repository to `https://github.com/flyset/MyMCP`, and the tracked official client/permission prefix to `mymcp`, while preserving routes, `list_tools`, plugin `mnemosyne`, `memory_*`, `MNEMOSYNE_*`, `~/.mnemosyne`, storage, record, logging, consent, and domain identities. The former repository URL redirects; repository and operational checks are complete. The public non-draft, non-prerelease release is [`MyMCP 0.2.0: public-host cutover`](https://github.com/flyset/MyMCP/releases/tag/mymcp-v0.2.0), tagged `mymcp-v0.2.0` at `c2852bc`.
- **MCPB boundary** — MCPB may later package MyMCP as one independently launchable complete MCP server; it is not MyMCP's native plugin distribution, manifest, logical author API, or external-worker boundary.
- **Tool registration** — one explicit in-process pairing of a Tool definition and its callable handler; the generic registry snapshots ordered registrations for immutable discovery and schema-aware dispatch without selecting domain Tools or providing plugin discovery.
- **Activated tool** — an immutable Phase 1 `ActivatedTool` pairing a qualified capability identity, complete Tool definition, handler, trusted effect metadata, and consent requirement.
- **Plugin contribution** — an immutable `PluginContribution` containing one plugin identity/version and its selected `ActivatedTool` values; host composition validates it before binding and registry construction.
- **Host-owned public binding** — the Phase 1 mapping from a qualified capability to its flat endpoint-visible Tool name. `list_tools` and reserved prefixes remain host-owned; Mnemosyne `memory_*` names are pinned compatibility bindings.
- **Mnemosyne adapter** — the trusted in-process Mnemosyne 0.1.0 adapter in `mymcp/plugins/mnemosyne/plugin.py` over canonical registrations. One ordered declaration table derives its complete immutable definition and gate-selected contribution; fixed bootstrap validates it against the packaged manifest before generation. It is part of the extracted bundled plugin, not external activation or a public plugin ABI.
- **Runtime-bound dispatch** — MCP dispatch constructed from an injected `HostRuntime`; `create_app(runtime)`, `tools/list`, `list_tools`, and `tools/call` use that runtime rather than a global application or startup module.
- **Mnemosyne configuration boundary** — the plugin-owned `mymcp.plugins.mnemosyne.configuration` owner of the unchanged memory root, `MNEMOSYNE_*` overrides, strict `~/.mnemosyne/config.toml` parser, source-safety checks, bounded failures, and immutable mutation settings; it imports no MCP Tool, FastAPI, or route package and is not dynamic configuration discovery.
- **MyMCP host** — the repository, distribution, and top-level Python package that hosts HTTP/MCP runtime, kind-qualified Tool composition, immutable runtime generations, explicit bootstrap, fixed packaged-manifest parsing, and the extracted in-process Mnemosyne bundled plugin. The public-host release is MyMCP/`mymcp` `0.2.0`; repository migration and release publication are complete. External installation/activation/isolation, lifecycle publication, gateway governance, and public metadata projection remain deferred.
- **Mnemosyne memory domain** — the user-governed memory behavior hosted by MyMCP. It permanently retains plugin `mnemosyne`, configuration, storage, record, logging, consent, and `memory_*` Tool identity under the MyMCP public host.
- **Memory** — protocol and product shorthand for user-approved durable records held outside the model; it does not mean that the model possesses durable personal memory and is never a secret store.
- **Memory substitute** — an external, notebook-like system that preserves approved records and retrieves selected records into temporary model context, providing continuity without giving the model intrinsic memory.
- **Legacy memory record** — a compatible schema-version-1 JSON record with ID, content, and optional title/tags; it remains readable without background rewriting or invented metadata.
- **Memory collection** — an optional stable organizational partition beneath a version-2 namespace; its ID affects the path while its mutable label does not.
- **Memory kind** — the controlled semantic role of a version-2 record, such as `preference`, `decision`, `state`, `event`, or `reference`; it is constrained by scope, immutable after creation, and is not a path segment.
- **Kind guidance** — canonical bounded writing guidance keyed by the `(scope, kind)` pair; `memory_remember` renders scope-specific guidance in complete branches and groups all guidance by scope for flat clients.
- **Event memory** — a completed occurrence represented by immutable kind `event`, currently allowed only under `project`; it is distinct from `state`, which describes a current condition.
- **Event occurrence time** — immutable structural `occurred_at` on an event, required in strict UTC-second `YYYY-MM-DDTHH:MM:SSZ` form and distinct from server-controlled creation/update times; it participates in duplicate identity and is absent from non-events.
- **Memory lifecycle** — the active/archived state and positive revision of a version-2 record; archived records are inspectable but excluded from normal recall, while forgotten records are physically absent.
- **Memory namespace** — the required stable routing identity beneath a scope, such as a project, relationship subject, preference domain, practice domain, self aspect, or knowledge topic.
- **Memory provenance** — bounded metadata describing an approved record's origin and server-controlled recording mechanism; it contains no prompt, transcript, or unverifiable consent claim.
- **Memory inspection** — exact read-only retrieval of one canonical or legacy record through a versioned structured reference; it includes archived canonical memory and never accepts a path or broad selector.
- **Memory inspection request** — exactly one versioned reference: schema version, scope, and ID for legacy memory, plus namespace ID and nullable collection ID for canonical memory.
- **Memory inspection result** — `status: ok` with one exact user-visible record and its versioned reference; canonical results include persisted metadata and lifecycle, while legacy results contain no invented canonical fields.
- **Memory listing** — complete, deterministic, read-only enumeration of every valid record in one bounded scope or canonical container; unlike recall it uses no query, ranking, positive-match threshold, or five-result cap, and unlike inspection it returns no record content.
- **Memory list selector** — exactly one required scope plus an optional canonical namespace and omission-sensitive collection selector: omitted collection means every collection state, null means collectionless only, and a string means one exact collection.
- **Memory list request** — either an initial selector with optional page size from 1 through 100, or the identical selector with an opaque continuation cursor and no page-size key; it accepts no path, query, tag, content, arbitrary filter, or cross-scope request.
- **Memory list item** — compact selection metadata with an inspect-compatible reference, nullable title, and inspectability; canonical items additionally contain kind and lifecycle state, while content and internal storage metadata remain absent.
- **Memory inspectability** — whether a listed reference is `exact` or `ambiguous`; every canonical and unique legacy reference is exact, while all sources sharing one duplicate legacy identity are ambiguous.
- **Memory list page** — the ordered list items plus page number, returned-item count, total selected count, total page count, whether more records remain, and a nullable next cursor; an empty inventory is a successful page with zero counts.
- **Memory list cursor** — a bounded opaque HMAC-authenticated continuation bound to one process, selector, complete selected valid-record snapshot, next offset, and page size; it contains no path, content, fingerprint, or reversible storage identity and is not persisted.
- **Memory remember** — the explicit, consent-gated MCP mutation that validates one bounded approved draft and, only when operator-enabled, atomically creates a canonical version-2 record or returns an exact duplicate outcome.
- **Memory revision** — the independently enabled, consent-gated MCP mutation that atomically replaces the complete caller-mutable state of one exact canonical version-2 record at its current expected revision while preserving stable identity and lifecycle state.
- **Memory revision request** — exactly one canonical version-2 reference, a positive current `expected_revision`, required complete replacements for nullable namespace label, nullable title, content, and tags, plus a required nullable collection label only when the reference has a collection ID; a collectionless reference may omit that structurally nonexistent label. It accepts no patch, legacy identity, path, immutable field, lifecycle target, timestamp, provenance replacement, or model confirmation.
- **Revision mutable state** — namespace label, the label of an existing collection, title, content, and tags; collection presence/ID, kind, and event occurrence time are immutable.
- **Revision outcome** — `revised` or `already_current`, with only the canonical versioned reference and lifecycle; changed outcomes increment revision once and update time, while no-op outcomes do not write.
- **Revision enablement** — the startup-fixed revision-only gate controlled first by exact `MNEMOSYNE_MEMORY_REVISE_ENABLED`, otherwise by strict `[memory].revise_enabled`, and finally by a disabled default; it is independent of all other mutation gates and MCP-client consent.
- **Revision content policy** — the shared bounded signature detector applied to replacement labels, title, content, and tags before storage access; refusal preserves only the canonical source field and one broad reason for MCP projection.
- **Disallowed-content refusal** — a remember or revision Tool error with `status: refused`, code `disallowed_content`, one bounded caller-visible `field`, one broad `reason`, and stable safe-retry guidance. Remember reports `namespace`, `collection`, `title`, `content`, or `tags`; revision reports `namespace_label`, `collection_label`, `title`, `content`, or `tags`. The five reasons are `private_key_shape`, `credential_shape`, `compact_token_shape`, `payment_card_shape`, and `government_identifier_shape`. Only the deterministic first match is represented; no rejected value, tag index, offset, regex, provider-specific detector, fingerprint, path, or exception detail is returned or logged. The metadata supports review of benign formatting and never authorizes obfuscating suspected sensitive data; every revised call still requires user approval.
- **Uncertain replacement outcome** — atomic replacement may have published the new record, but directory durability was not confirmed; exact inspection is required before any newly approved retry. It applies to revise, archive, and restore and is distinct from uncertain deletion.
- **Memory archive** — the explicit consent-gated MCP mutation that revision-checks one exact active canonical memory, atomically changes it to archived, and removes it from normal recall without deleting it.
- **Memory restore** — the explicit consent-gated MCP mutation that revision-checks one exact archived canonical memory, atomically changes it to active, and returns it to normal recall.
- **Memory forget** — the independently enabled, irreversible MCP mutation that revision-checks one exact archived canonical version-2 memory and physically removes its source file without creating a tombstone.
- **Memory forget request** — exactly one canonical version-2 reference plus its positive current `expected_revision`; it accepts no legacy identity, path, content, fingerprint, target state, timestamp, or model confirmation.
- **Memory forget outcome** — `forgotten` with only the same canonical versioned reference; a later call returns `not_found` because no tombstone exists.
- **Forget enablement** — the startup-fixed forget-only gate controlled first by exact `MNEMOSYNE_MEMORY_FORGET_ENABLED`, otherwise by strict `[memory].forget_enabled`, and finally by a disabled default; it is independent of remember, archive/restore, and MCP-client consent.
- **Uncertain deletion outcome** — unlink may have succeeded but parent-directory durability was not confirmed; the caller must inspect the same reference before any newly reviewed and approved retry, without treating absence as tombstone-backed secure-erasure proof.
- **Lifecycle mutation request** — exactly one canonical version-2 reference plus its positive current `expected_revision`; it accepts no legacy identity, path, content, target state, timestamp, or model confirmation.
- **Lifecycle mutation outcome** — `archived`, `already_archived`, `restored`, or `already_active`, with only the canonical versioned reference and lifecycle; changed outcomes increment revision once, while current-state outcomes do not write.
- **Archive/restore enablement** — the startup-fixed reversible-lifecycle gate controlled first by exact `MNEMOSYNE_MEMORY_ARCHIVE_RESTORE_ENABLED`, otherwise by strict `[memory].archive_restore_enabled`, and finally by a disabled default; it is independent of remember enablement and MCP-client consent.
- **Memory remember request** — nine required caller-owned scope, namespace, optional collection, kind, language, title, content, tags, and public-origin fields, plus structural `occurred_at` required exactly for project events. All ten possible fields are published in top-level properties for flat-client compatibility while only the nine unconditional fields are globally required; complete scope branches retain stricter dimension and event-time constraints. Public origin is provenance context, not consent, and the request never contains a path or server-owned operational field such as `recorded_via`.
- **Remember content policy** — bounded signature-based refusal applied by the shared domain before duplicate discovery or writes; it recognizes declared secret, credential, compact-token, payment-card, and government-identifier shapes, preserves only canonical first-match field/reason metadata, and is not complete semantic DLP. Compact-token recognition requires JOSE compact-serialization evidence: a base64url JSON header segment beginning `eyJ` followed by two further base64url segments. Ordinary dotted text—versions, dates, hostnames, module paths—is accepted.
- **Remember enablement** — the startup-fixed, remember-only operator gate controlled first by an exact `MNEMOSYNE_MEMORY_REMEMBER_ENABLED` process override, otherwise by the optional strict `~/.mnemosyne/config.toml` `[memory].remember_enabled` boolean, and finally by a disabled default; it never establishes MCP-client consent.
- **Remember outcome** — `remembered`, `already_exists`, or `existing_archived` with only a structured reference and lifecycle; validation, refusal, conflict, disabled, and storage conditions are bounded Tool errors.
- **Memory record** — one user-visible, versioned JSON source-of-truth file; canonical version-2 records separate scope, namespace, collection, kind, language, content, tags, provenance, persistence timestamps, optional event occurrence time, and lifecycle.
- **Memory reference** — a versioned structured identity used instead of a client-supplied path; version 1 contains scope and record ID, while version 2 also contains namespace ID and nullable collection ID.
- **Memory root** — the operator-controlled local directory containing the six fixed memory scope directories; it defaults to `~/.mnemosyne/memory` and is initialized lazily with private newly created directories only when an enabled, valid, policy-accepted remember call reaches canonical creation.
- **Memory recall request** — a narrow, model-generated description of user-specific context that could materially affect the current response.
- **Memory scope** — the single required high-level category describing what a memory operation concerns: `self`, `relationship`, `preference`, `practice`, `project`, or `knowledge`.
- **Memory scope directory** — one fixed top-level directory beneath the memory root selected by a validated memory scope; recall and listing never accept a client-supplied path.
- **Shared memory domain** — the tool-independent `mymcp/plugins/mnemosyne/memory/` package that owns Mnemosyne scopes, per-pair kind definitions/guidance, records, event occurrence semantics, normalization, paths, storage, retrieval, listing selection/order/pagination/cursors, revision mutable-field and content policy, first-match refusal field/reason classification, lifecycle policy, atomic replacement, replacement uncertainty, and shared errors.
- **Recall tags** — optional, bounded, free-form descriptive labels attached to a memory recall request; exact normalized overlap with record tags is a ranking signal, not a required filter.
- **Recall match evidence** — the sorted terms and tags explaining which request signals matched a returned memory record; it excludes paths and internal scores.
- **Recall reference continuity** — the inspect-compatible versioned reference included with every successful recall match so an active canonical or legacy result can be selected exactly without exposing a path.
- **Memory recall** — read-only retrieval that validates a recall request, searches only its selected scope directory, and returns bounded approved records with inspect-compatible references without persisting the request.
- **Memory mutation** — an explicit create, revise, archive, restore, relocate, or physical-forget operation; domain primitives are disabled by default, while remember, revise, reversible archive/restore, and archived-only forget are implemented MCP mutations behind independent startup gates.
## Contract Terms

- **Public MCP contract** — the externally observable behavior of endpoints, protocol methods, tool names, input schemas, and result or error shapes.
- **Tool schema** — the declared name, description, and input contract for an MCP tool.
- **Tool argument compatibility normalization** — central MCP dispatch adaptation that uses the selected Tool schema to remove at most one extra JSON-stringification layer where strings are disallowed and the decoded type is allowed; it leaves native values, legitimate strings, malformed values, and repeatedly encoded values unchanged for normal Tool validation.
- **Server version marker** — the endpoint-owned public compatibility version returned by initialize and `/version` and prefixed to `list_tools` so an operator can distinguish a stale process after restart. The MyMCP public-host release marker is `mymcp 0.2.0` and remains equal to the package version; the marker remains endpoint-owned and normally releases the same value. It is not a dynamic source-control identifier, plugin version, or runtime generation.
- **JSON-RPC error** — a protocol-shaped error response with a stable code and explanatory message.
- **MCP notification** — an MCP message without an `id`; it receives HTTP `202` with no JSON-RPC response body.
- **Invalid parameters** — JSON-RPC error `-32602`, returned when a request supplies a non-object `params` value or a `tools/call` request supplies non-object `params.arguments`; the valid request ID is preserved and no Tool handler runs.
- **Invalid request** — JSON-RPC error `-32600`, returned with `id: null` when the top-level request envelope is not an object.
- **No matches** — a successful memory recall result with `status: no_matches` and an empty `memories` array when the selected scope is absent or contains no positively ranked valid record.
- **Empty inventory** — a successful memory list result with `status: ok`, no items, page number 1, zero returned/total/page counts, `truncated: false`, and no next cursor; unlike `no_matches`, it represents complete enumeration rather than failed relevance matching.
- **Retrieval error** — a Tool error indicating that a validated recall request could not safely read its source or exceeded the candidate limit; it does not expose internal filesystem details.
- **Memory list error** — a bounded Tool error for invalid object fields, scope, namespace, collection, page size, or cursor; stale continuation; candidate overflow; unsafe/unavailable storage; or unexpected failure after protocol-level argument validation. Non-object `tools/call` arguments are instead an `Invalid params` JSON-RPC error before Tool dispatch. Neither form returns a partial inventory, selector value, cursor, record content, path, fingerprint, or exception detail.
- **Invalid list cursor** — `status: invalid_request`, code `invalid_cursor`, returned for malformed, current-process-tampered, selector-mismatched, page-size-incompatible, or otherwise invalid continuation; the caller must start a fresh listing.
- **Stale list cursor** — `status: conflict`, code `stale_cursor`, returned after process restart or when the selected valid-record snapshot changed through addition, removal, relocation, byte rewrite, lifecycle change, or a valid/invalid transition; the caller must start a fresh listing.
- **Inspection error** — a Tool error with a stable bounded code for an invalid, missing, ambiguous, excessive, unsafe/unavailable, or unexpectedly failed exact inspection; it exposes no path, record content, or underlying exception.
- **Lifecycle mutation error** — a Tool error with a stable bounded code for invalid canonical identity/revision, disabled mutation, missing memory, stale revision, publication conflict, uncertain post-publication replacement, unsafe/unavailable storage, or unexpected failure; it exposes no submitted value, path, record content, or underlying exception.
- **Memory revision error** — a bounded Tool error for invalid canonical identity/revision or replacement fields, collection mismatch, policy refusal, disabled mutation, absence, stale revision, write conflict, uncertain replacement, unavailable storage, or unexpected failure; replacement validation uses a matching public field and field-specific bounded message, while content refusal uses the shared field/reason contract, without exposing content, complete arguments, paths, fingerprints, or exception detail.
- **Memory forget error** — a bounded Tool error for invalid canonical identity/revision, disabled mutation, active state, absence, stale revision, changed storage, unsafe/unavailable storage, uncertain deletion, or unexpected failure; it exposes no record content, path, fingerprint, complete arguments, or exception detail.
