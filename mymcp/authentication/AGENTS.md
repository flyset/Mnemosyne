# Authentication Scope Rules

- Own transport-neutral normalized principals, bounded evidence/context, adapter results, exact evidence routing, and immutable Authentication composition here.
- Import only the standard library and this package. Do not import FastAPI, routes, MCP, Governance, plugin contracts, plugins, or host configuration.
- `oauth.py` is the standard-library-only shared helper: it owns the canonical `validate_oauth_issuer`, the `oauth-jwt-jwks-v1` profile identity, and loopback resource/audience derivation. Host configuration and host Authentication composition import it so that strict issuer/resource validation never loads the `PyJWT[crypto]` runtime.
- The `oauth-jwt-jwks-v1` foundation (`adapters/oauth_jwt.py`) is the only module here permitted to import the declared `PyJWT[crypto]` runtime dependency; contracts, routing, and every other adapter module remain standard-library-only.
- The OAuth adapter/discovery modules are loaded only through a lazy function-local import inside host Authentication composition, and registered only when a schema-5 document enables OAuth. Ordinary host startup (app, CLI, configuration, operator-bearer, anonymous, schema 1-4) must never load them or the isolated `PyJWT[crypto]` runtime, and they are never re-exported from `mymcp.authentication` nor eagerly imported by the `adapters` package.
- `adapters/oauth_discovery.py` is the standard-library-only startup loader: it derives the RFC 8414 metadata URL from one canonical HTTPS issuer and acquires one immutable `OAuthJwtSnapshot` through exactly two bounded no-redirect fetches (metadata then same-origin HTTPS `jwks_uri`) behind an injected fetch seam that owns certificate/hostname validation and transport bounding; the concrete standard-library reference implementation of that seam is `bounded_https_fetch`. The running validator performs no metadata/JWKS refresh, introspection, fallback, or provider call; rotation and key removal are visible only after restart.
- The `oauth-jwt-jwks-v1` adapter claims the same exact Authorization/Bearer route as `operator-bearer-v1` because the HTTP boundary cannot distinguish token shapes; schema-5 configuration exclusion guarantees these two Bearer methods are never composed together. Token shape never selects an adapter.
- Validate exactly compact duplicate-free RS256 `at+jwt` tokens with strict header, key, claim, time, and audience rules, a 30-second skew, and a five-minute maximum lifetime; unsupported, malformed, ambiguous, wrongly issued or targeted, or expired tokens fail closed.
- Return only the opaque `oauth-jwt-v1:` SHA-256 issuer+NUL+subject projection as an adapter-local subject; raw claims never cross the adapter boundary.
- Never expose credentials, raw evidence, tokens, claims, keys, issuer or JWKS URIs, provider responses, or exception details through principals, failures, representations, or logs.
- Route submitted evidence to exactly one registration by host-derived descriptor. Never probe sequentially or fall back to another adapter or anonymous access. Protocol failure is bounded and content-free.
- Anonymous is an independent configured mode for evidence-free requests only.
- The host constructs canonical principal identities; adapters return only validated adapter-local subjects.
